# Retrieval implementation

The extension reads the current ChatGPT, Claude or Gemini page in an isolated script after a toolbar click. It supports the observed guest message attributes and the signed-in message attributes, without private API requests or authentication-token access. `activeTab` plus `scripting` grants temporary access to the clicked tab.

It scrolls to the start and end, waits for stable message snapshots, and requires every previously observed message to remain present in order. Virtualised content that disappears, changing replies, navigation, loading indicators, missing IDs, and unknown message shapes stop export. The original scroll position is restored. The transcript is read twice before saving to catch changes, without requiring a second user action. Omissions are marked in the output; export downloads directly with `saveAs: false`.

This establishes a stable rendered transcript, not a server-side history proof. Export metadata identifies the rendered scope and does not assert full-history completeness. Citation labels are preserved; only source URLs actually present in message content are included. Attachments are marked as omissions. Long or virtualised layouts that cannot retain a stable transcript fail explicitly. See the dated verification record for live evidence; full-history completeness is not established.

Guest DOM evidence: the owner supplied six messages at `/uc/<UUID>`. Messages use `data-message-role`, user text uses `data-user-message-copy`, assistant content uses `data-assistant-markdown`, and completed answers have `data-message-complete`. Ads may be inside the message container but outside its content; only message content is converted. Boot-time JSON may contain no rows even when the page contains messages, so it is not used as a history source.

## Current history renderer — 8 October 2026

Live inspection of the owner-provided history chat established a third message layout: `data-chatgpt-search-message-ids` identifies visible message units, `data-user-message-bubble` contains user text, and `data-chatgpt-selection-message-id` identifies the displayed assistant answer. Search units may reference several internal message IDs; the exporter uses the selected answer ID and its `data-markdown-text-style` content, not every referenced internal record. Conversation identity and complete turn state are checked.

The scrolling container uses `column-reverse` and negative scroll offsets. Both ends are now checked with that geometry, and the original position is restored. Code blocks use `data-markdown-copy="code-block"` with a CODE element rather than PRE; controls marked `exclude` are removed. Tests use hand-written synthetic markup only. Live inspection recognised eight messages without retaining or logging their text.

## Deep Research — 8 October 2026

The owner supplied a conversation with a completed report rendered inside a `Deep research` iframe under `data-mcp-app-frame`. Its origin is a sandbox app at `https://mcp-app-<hex>.web-sandbox.oaiusercontent.com`; a sandbox wrapper can contain another report frame. Ordinary `activeTab` access to ChatGPT cannot read this origin. Optional host access is therefore declared for the sandbox domain and requested only for the detected exact app origin from an explicit export click. No extra required permission, automatic content script or request interception is used.

The report page’s `_reportPage_` component contains the full Markdown even when its visual preview is clipped. A bounded `MAIN`-world traversal from its heading reads only the observed component’s `report`, `reportMessageId`, `runCompletedAtMs` and `contentReferences`. The reader returns no session state, activity records or uncited search results. It checks completion and a stable snapshot. `grouped_webpages` reference ranges become numbered citations with validated HTTP(S) source URLs. `sources_footnote` contributes the report’s source footer, including the observed zero-length end-of-report metadata range. Unknown reference types, invalid/overlapping ranges, unsafe URLs and unresolved internal citation tokens block saving. Report frames must correspond unambiguously to the current chat’s iframe URLs. The conversation and reports are read again before saving.

Some displayed assistant units combine several source messages and have a conversation selection marker without a single selected-message marker. Those units are exported once with a stable `rendered-` identifier; their original source IDs are retained in `renderedSourceMessageIds` metadata and participate in change detection. No alternative branch is inferred from the last source ID.

## Claude and Gemini — shared reader

Exact saved-chat origins/routes select two small branches inside the same self-contained DOM reader. Formatting, scrolling, stability checks, revalidation and saving stay shared; there are no provider settings, private endpoints or new required permissions.

The observed Claude history uses `data-testid="user-message"` and `assistant-message`, `data-is-streaming="false"` on completed replies, and `.standard-markdown` for answer blocks. User paragraphs sit in a `display: contents` wrapper, so content containers are checked through their visible children. Assistant `data-turn-key` supplies stable IDs; DOM-generated user IDs are ignored. When a stable message ID is unavailable, a SHA-256 of role/text/source content plus duplicate occurrence identifies the rendered message. These are local export identifiers, not authenticated server IDs.

Gemini saved-chat routes include `/app/<hex-id>` and `/u/<account>/app/<hex-id>`. Its reader uses `user-query` / `model-response` units with query and Markdown content. Live inspection confirmed these Gemini content markers and `aria-busy="false"` on completed Markdown blocks. The reader requires that completion marker even if no Stop button is visible; details are recorded separately. Unknown message boundaries, streaming replies and embedded frames inside messages stop export. Content in separate Claude artifacts or Gemini Canvas panels is outside the rendered-message scope and is explicitly disclosed in help and metadata. Gemini Deep Research is not promised.
